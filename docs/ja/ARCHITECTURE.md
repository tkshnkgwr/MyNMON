# システム設計書 (ARCHITECTURE.md)

[English](../en/ARCHITECTURE.md) | **日本語版**

本ドキュメントは、超軽量 CUI システムモニター `MyNMON` のアーキテクチャ設計、コンポーネント構成、採用技術スタック、および条件付きコンパイル（Cargo Features）によるモジュール分離方針を定義した設計書です。

---

## 1. 全体構成およびモジュール分割

`MyNMON` は関心の分離に基づき、以下の 4 つのソースファイルに分割されています。

```text
src/
├── main.rs      # エントリポイント、二重起動チェック、CLI引数解析、TerminalGuard (RAII)、メインイベントループ
├── state.rs     # アプリケーション状態構造体 MonitorState の定義 (feature制御)
├── ui.rs        # Crossterm を用いたターミナル描画関数群 (feature制御)
└── utils.rs     # 時間フォーマット、ASCIIバー生成、マルチバイト文字幅計算、単体テスト
```

### 安全性・応答性の設計ポイント

- **ターミナル状態復元（RAII ガード）**: `TerminalGuard` 構造体の `Drop` 実装により、正常終了時だけでなくエラー発生による早期リターン時にも raw モード解除・オルタネートスクリーン離脱・カーソル再表示を確実に実行します。
- **メトリクス更新とUI描画の分離**: システムメトリクスの取得（`sys.refresh_all()`, `disks.refresh(true)`, `networks.refresh(true)`）およびプロセス差分検知は設定された更新間隔（`tick_rate`）の経過時のみ実行し、キー入力時は即座に UI 再描画のみを行うことで高応答性と正確なネットワーク速度（KB/s）算出を両立しています。

## 3. Cargo Features（条件付きコンパイル）アーキテクチャ

用途や組み込み環境に応じたバイナリサイズの最適化のため、各監視モジュールを Feature フラグとして分離しています。

```text
               ┌─────────────────────────────┐
               │    default = ["cpu", ...]   │
               └──────────────┬──────────────┘
                              │
  ┌──────────┬──────────┬─────┴────┬──────────┬──────────┐
  │          │          │          │          │          │
  ▼          ▼          ▼          ▼          ▼          ▼
[cpu]      [mem]      [disk]     [net]      [proc] ◄── [diff]
```

- 各機能 (`cpu`, `mem`, `disk`, `net`, `proc`, `diff`) のデータ取得・描画ロジック・キー操作イベントは、`#[cfg(feature = "...")]` によりコンパイル時に組み込み/除外されます。
- `diff`（プロセス増減ログ）機能はプロセス情報の比較を行うため、`proc` feature に自動的に依存します。
