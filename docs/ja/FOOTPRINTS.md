# フットプリント測定レポート (FOOTPRINTS.md)

[English](../en/FOOTPRINTS.md) | **日本語版**

本レポートは、リリースビルドにおける `MyNMON` のバイナリサイズおよびメモリ使用量の実測値を記録したものです。

---

## 1. 測定環境

- **OS**: Windows 11 Pro (ビルド 26200)
- **CPU**: Intel(R) Core(TM) i7 / 12スレッド
- **RAM**: 16 GB
- **Rust バージョン**: rustc 1.100.0 (2026-11-20 計測時点)
- **主要依存クレート**: `sysinfo 0.40.4`, `crossterm 0.29.0`, `common_lib 0.4.0`
- **Cargo プロファイル設定 (Cargo.toml)**:

  ```toml
  [profile.release]
  opt-level = 'z'       # サイズ優先最適化
  lto = true            # リンク時最適化
  codegen-units = 1     # コンパイル単位の統合
  panic = 'abort'       # 巻き戻し無効化
  strip = true          # シンボル情報の削除
  ```

---

## 2. 測定結果

### 2.1 実行バイナリサイズ

最適化を施したリリースプロファイルでビルドされた実行ファイルのサイズ比較です。

| ビルド構成                   | コマンド                                                     | ファイルサイズ                 |
| :--------------------------- | :----------------------------------------------------------- | :----------------------------- |
| **フル機能ビルド (default)** | `cargo build --release`                                      | **302,592 バイト (約 296 KB)** |
| **最小構成ビルド (cpuのみ)** | `cargo build --release --no-default-features --features cpu` | **256,000 バイト (約 250 KB)** |

> [!TIP]
> `sysinfo 0.40.4` へのアップデート（旧バージョンの `windows v0.52` や `rayon` 依存の解消）により、フル機能ビルドでも従来の約 672 KB から **約 296 KB（約 56% 削減）** へと大幅に軽量化されました。さらに Cargo Features で `cpu` のみの最小構成にすると **約 250 KB** まで削減可能です。

### 2.2 実行時メモリフットプリント

実際にアプリケーションを起動し、2秒間稼働させた時点でのプロセス物理メモリ使用量（Working Set）を測定しました。

- **プロセス名**: `MyNMON.exe`
- **物理メモリ使用量 (WorkingSet64)**: **約 21.3 MB (22,409,216 バイト)**

> [!NOTE]
> アプリケーション内部の `sysinfo` クレートが内部バッファに全プロセスのリストやハードウェア統計をキャッシュしているため、20 MB 強のメモリ空間を確保しています。これは CUI システムモニターとしては十分に軽量であり、他のアプリケーションのパフォーマンスを阻害しません。

---

## 3. 総評

`MyNMON` は、フル機能構成でも **約 296 KB**（最小構成で **約 250 KB**）という極めてコンパクトなバイナリサイズと、低負荷・低メモリ消費（約 21.3 MB）を実現しています。
これにより、サーバー監視用途やリソースが極めて制限された環境でも、問題なくリアルタイム監視に使用することができます。
今後機能を追加する際も、このフットプリント水準（バイナリ 350 KB 以下、メモリ 25 MB 以下）を維持するよう努めます。
