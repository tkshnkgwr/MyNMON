# AI開発指示書 (INSTRUCTIONS.md) - MyNMON

[English](../en/INSTRUCTIONS.md) | **日本語版**

本文書は、AIエージェント（大賢者）が `MyNMON` のソースコードを変更・保守・機能追加する際に遵守すべきガイドラインおよび開発規約です。

---

## 1. 開発原則

1. **CUI 描画品質とフリッカー防止の徹底**:
   - 画面の全体クリア (`terminal::Clear(ClearType::All)`) を行わず、カーソルを `(0, 0)` に戻した上書き描画を行うこと。
   - `UntilNewLine` による行末消去、および描画完了後の `FromCursorDown` による下部消去を組み合わせ、テキストの残存を防ぐこと。
   - 画面サイズが「横80文字以上、縦20行以上」を下回る場合は、描画処理をスキップして警告を表示すること。
2. **二重起動防止**:
   - Windows環境においては、`common_lib::check_single_instance` を用いた Named Mutex による多重起動防止ロジックを必ず維持・動作させること。
3. **リリースサイズとメモリの最適化**:
   - メモリフットプリント（25MB以下）およびバイナリサイズ（350KB以下）を維持すること。
4. **他言語開発経験者に配慮した解説方針**:
   - ユーザーは他言語での開発経験をお持ちですが、Rust固有の専門用語（所有権、トレイト、ライフタイム等）には不慣れです。一般的なプログラミング概念に置き換えるか直感的な補足解説を添えて報告してください。

## 2. コードスタイルのガイドライン
- **フォーマット規則**: `cargo fmt` の標準スタイルに従ってください。
- **型と変数名**:
  - 構造体 / 列挙型: `PascalCase` (例: `MonitorState`)
  - 関数 / 変数 / モジュール: `snake_case` (例: `draw_cpu_total`)
  - 定数: `SCREAMING_SNAKE_CASE` (例: `MUTEX_NAME`)
- **エラー処理**:
  - パニック (`panic!`, `unwrap()`) の使用は極力回避し、適切なフォールバック処理またはエラー値を返すようにしてください。

## 3. 自動ドキュメンテーションと更新ルール (モジュール化退避)
コード追加・変更・リファクタリング・依存更新時には、**英語版 (`docs/en/`) と日本語版 (`docs/ja/`) の両ドキュメント**を更新・完全同期します。
※**ただし、Markdownファイル（`.md`）のみの変更時は自動ドキュメンテーションおよびドキュメント自動更新は適用外とします。**

| ドキュメント (EN / JA) | 役割および更新ルール |
| :--- | :--- |
| `CHANGELOG.md` | 変更履歴。`docs/*/CHANGELOG.md` に日付 `## [X.Y.Z] - YYYY-MM-DD` とカテゴリ (`### 追加` / `### 変更` / `### 修正` / `### 削除`) で最新を上に追記。 |
| `SPEC.md` | キー操作、CLI引数、表示ルール、監視メトリクス、技術スタックの定義。 |
| `DIAGRAM.md` | システム構成、イベントループ順序、データ取得フローを示す Mermaid ダイアグラム。 |
| `README.md` / `README_JA.md` | 概要、ビルド・実行手順、要件。起動オプションや要件変更時に更新。 |
| `FOOTPRINTS.md` | パフォーマンス、バイナリサイズ、メモリ使用量の計測記録。 |
| `ARCHITECTURE.md` | 設計概要、モジュール構成、データフロー、Cargo Features によるコンパイル時分離構造。 |
| `INSTRUCTIONS.md` | 命名規則、エラーハンドリング、モジュール分割、回答フォーマット。 |
| `TODO.md` | タスク管理（Done / Todo / Backlog）。 |
| `TESTING.md` / `TEST_REPORT.md` | テスト方針・実行手順 / 過去の検証履歴・自動/手動検証結果レポート。 |
| `RELEASE.md` / `SECURITY.md` | リリース手順 / セキュリティ設計原則・サポート要件・報告手順。 |
| `CONTRIBUTING.md` | 開発参加者・貢献者向けガイドライン。 |
| Rustdoc (ソース内コメント) | `///` や `//!` による構造体・関数・モジュールの仕様記述。仕様変更時にソース内コメントを同期。 |

## 4. 品質管理・自動テストと事前検証ルール (モジュール化退避)
- **1,000 行制限ルール**:
  - 単一のプログラムソースファイル（例: `src/*.rs`）の行数が **1,000 行** を超えた時点で、関心事・役割に応じたモジュール分割を提案・実施。
- **ローカル事前検証**:
  1. `cargo test`
  2. `cargo clippy --all-targets -- -D warnings`
  3. `cargo fmt --check`
  4. `cargo doc --no-deps --document-private-items`
